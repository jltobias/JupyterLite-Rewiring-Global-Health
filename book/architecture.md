# Architecture

The project uses a **browser-first / secure-handoff** architecture. JupyterLite supplies a low-friction learning runtime; cloud-native geospatial formats reduce unnecessary downloads; sensitive or computationally heavy work is handed off to approved full runtimes.

## Browser-first lane

Use public or synthetic data, COG/GeoJSON/Zarr/STAC resources, Pyodide-compatible Python, browser maps, charts, and deterministic teaching agents.

## Secure / heavy-compute lane

Use protected compute for sensitive health data, long-lived credentials, GPU inference, large calibration runs, or regulated workflows. The browser notebook can export a request, configuration, or derived non-sensitive artifact without exposing protected source data.

## What this repository actually runs

The Jupyter Book stores executed notebook outputs. JupyterLite serves clean-output copies and the shared `rewiring.py` module, so learners start from the source and can rerun it. The demo gallery reads a small, committed JSON cube generated by that same module. GeoJSON is the exchange boundary with GeoLibre. All core numerical examples use local synthetic data; Lab 01 can optionally request live satellite metadata.

Zarr 2.18.7 and xarray 2025.9.0 provide a bounded in-memory array round trip. SQLite operates on a materialized subset. Plotly supplies orbitable surfaces and time cubes; MapLibre supplies a separate extruded scene; the 2D demo uses native SVG and has a data-table alternative.

## AI integration boundary

JupyterLite AI is a browser extension included at build time. The site does not include a model service. The default lesson widget is a deterministic teaching backend. An institutional extension can connect to an authenticated gateway, but must define authorization, allowed context, retention, rate limits, provenance, and response validation. The notebook adapter demonstrates a request contract and never executes returned text.

## Files and updates

`scripts/build_notebooks.py` authors the lessons; `execute_notebooks.py` executes them and fails on errors; `check_models.py` verifies model/data invariants; `prepare_site.py` stages demos and clean copies. GitHub Actions builds the book, bundles JupyterLite, and deploys the combined site. Browser-local edits persist independently of later site revisions; download important work before refreshing local content.
